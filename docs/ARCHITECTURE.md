# Архітектура FreelanceCRM простими словами

Цей файл відповідає на одне питання: **«Я хочу щось змінити. У якому файлі це шукати?»**
Тут немає складних слів. Якщо потрібно знайти, де що лежить, починай із розділу
«Хочу змінити... Іду сюди» нижче.

## 1. Проєкт одним абзацом

Сайт зроблено на Next.js. Кожна **папка** в `src/app/[lang]/` це **сторінка сайту**.
Папка `clients` відповідає адресі `/uk/clients`, папка `calendar` адресі `/uk/calendar`.
Усередині кожної такої папки є файл `page.tsx`: він малює сторінку. Якщо поруч є `actions.ts`,
там лежать **дії кнопок** (що робить кнопка «Зберегти», «Видалити», «Зв'язався»).

Дані зберігаються в базі Neon. Працює з базою папка `src/lib/`. Шматки інтерфейсу,
які повторюються (меню, форма, мітка), лежать у `src/components/`. Усі **тексти** на сайті
лежать окремо, у чотирьох файлах-словниках (українська, англійська, польська, чеська).

Мову в адресі (`/uk`, `/en`, `/pl`, `/cs`) позначає `[lang]` у назві папки. Квадратні
дужки означають «тут може бути будь-яка мова».

## 2. Чотири шари, з яких складається будь-яка функція

Коли ти додаєш або змінюєш щось (наприклад, календар), майже завжди зачіпаєш ці шари
в такому порядку:

1. **База даних** (`migrations/`): які дані існують. Наприклад, колонка «дата нагадування».
2. **Логіка й запити** (`src/lib/`): функції, які читають і пишуть у базу. Наприклад, «дай усіх клієнтів із нагадуваннями».
3. **Сторінка й дії** (`src/app/[lang]/...`): що бачить людина і що відбувається по кнопці.
4. **Тексти** (`src/lib/i18n/dictionaries/*.json`): підписи, кнопки, підказки.

Кольори й вигляд (Tailwind) живуть прямо в `className` у файлах сторінок і компонентів,
а загальна палітра в `src/app/globals.css`.

## 5. Як працює клік по кнопці (на прикладі «Зв'язався»)

1. Людина натискає кнопку. Вона всередині `<form>` у `calendar/page.tsx` або в картці клієнта.
2. Форма викликає **дію** `completeFollowUpAction` з `clients/actions.ts` (це код, який виконується на сервері, а не в браузері).
3. Дія спершу **перевіряє, хто ти** (`requireApproved`). Форму в браузері можна підробити, тому сервер не вірить нікому.
4. Дія звертається до функції в `src/lib/clients.ts`, яка пише в базу. У самому запиті стоїть перевірка власника (`owner_id`), тож чужого клієнта змінити неможливо.
5. Дія каже сайту «оновись» (`revalidatePath`), і сторінка та кружечок у меню показують нові дані.

Майже кожна кнопка в проєкті працює за цим ланцюжком: **сторінка → дія → функція в lib → база**.

## 6. База даних

База: Neon Postgres. Три наші таблиці:

| Таблиця | Що в ній |
|---|---|
| `clients` | клієнти (ім'я, компанія, пошта, статус, нотатки, дата нагадування, власник `owner_id`) |
| `client_notes` | записи щоденника, кожен прив'язаний до клієнта; видаляються разом з ним |
| `profiles` | статус заявки (чекає, схвалено, відхилено), до якої дати оплачено, чи просили рахунок |

Користувачі (пошта, пароль, сесії) зберігаються окремо, у сервісі **Neon Auth**, а не в наших таблицях.

**Зміни бази** лежать у папці `migrations/` файлами `001_...sql`, `002_...sql` і так далі.
Правила:
- Хочеш нову колонку чи таблицю, створи **новий** файл з наступним номером (`006_...sql`).
- Уже застосований файл **ніколи не змінюй**.
- Застосувати: `npm run db:migrate`. Подивитися стан: `npm run db:status`.
- Подробиці: `migrations/README.md`.

Підключення до бази: `src/lib/db.ts` (адреса береться зі змінної `DATABASE_URL`).

## 7. Хто що бачить (доступ)

Усе вирішує файл `src/lib/auth/session.ts`:

- `getAccess()` визначає, хто ти: гість, заявка в обробці, схвалений, прострочений, адміністратор.
- `requireApproved()` стоїть на сторінках CRM (клієнти, календар, кабінет): пускає лише схвалених із діючою підпискою.
- `requireAdmin()` стоїть в адмінці: усім іншим показує «не знайдено».
- Кожен користувач бачить лише **своїх** клієнтів: це записано прямо в SQL-запитах (`owner_id`). Адміністратор у списку клієнтів бачить усіх, але нагадування в календарі в нього тільки власні.

Адресу `/uk/clients` без входу відкрити не вийде: сторінка перенаправить на вхід.

## 8. Мови й тексти

- Тексти лежать у `src/lib/i18n/dictionaries/uk.json`, `en.json`, `pl.json`, `cs.json`.
- Головний файл `uk.json`: типи беруться з нього. Якщо додати ключ в інший файл, а в `uk.json` його немає, збірка видасть помилку.
- **Новий текст додається у всі чотири файли**, інакше TypeScript не пропустить.
- Вибір мови зверху: `src/components/language-switcher.tsx`. Перенаправлення з `/clients` на `/uk/clients`: `src/proxy.ts`.

Щоб змінити лише слово на кнопці: знайди це слово в `uk.json`, зміни, потім так само в `en`, `pl`, `cs`.

## 10. Готові рецепти

### Змінити текст на сторінці
1. Знайди текст у `uk.json` (пошук по проєкту).
2. Зміни його, повтори в `en.json`, `pl.json`, `cs.json`.

### Додати нове поле клієнту (наприклад, «Телефон»)
1. `migrations/006_...sql`: `ALTER TABLE clients ADD COLUMN IF NOT EXISTS phone text NOT NULL DEFAULT '';`, потім `npm run db:migrate`.
2. `src/lib/types.ts`: додати поле в тип `Client`.
3. `src/lib/clients.ts`: додати колонку в `SELECT` (двічі: для адміністратора й для звичайного користувача), у `INSERT` і `UPDATE`.
4. `src/lib/client-input.ts`: додати поле в читання форми й перевірку.
5. `src/components/clients/client-form.tsx` і сторінки `new` та `edit`: показати поле.
6. `clients/[id]/page.tsx`: показати значення в картці.
7. Словники: підпис поля у чотирьох мовах.

### Додати новий розділ (нову сторінку з пунктом меню)
1. Створи папку `src/app/[lang]/назва/` з файлом `page.tsx` (за зразком `calendar/page.tsx`).
2. Додай пункт у `src/components/sidebar-nav.tsx`: у список `links`, а для телефона вирішуй, чи він у нижній панелі (`CRM_PRIORITY`), чи в «Ще».
3. Підпис пункту: словник, розділ `nav`, плюс у типи в `src/components/auth/nav-gate.tsx`.
4. Якщо сторінка тільки для схвалених, на початку викличи `requireApproved(locale)`.
5. Якщо її не треба показувати в Google, додай шлях у `src/app/robots.ts`.

### Змінити ціну
Лише `src/lib/plans.ts`, об'єкт `PRICE_PER_MONTH`.

### Змінити кольори
`src/app/globals.css`: змінні `--primary` (основний), `--sidebar` (меню) та інші. Для темної теми в цьому ж файлі є окремий блок. Кольори мають бути контрастними з текстом.

### Змінити, що рахує кружечок біля «Календар»
`src/lib/clients.ts`, функція `getDueSummary`. Зараз це прострочені й ті, що на сьогодні.

### Змінити пошук клієнтів
`src/app/[lang]/clients/page.tsx`, функція `matchesQuery`. Зараз шукає за іменем, компанією, поштою й нотатками.

### Вивести щось нове в адмінці
`src/app/[lang]/admin/page.tsx` (малювання) і `src/lib/profiles.ts` або `src/lib/stats.ts` (дані). Права вже перевірені файлом `admin/actions.ts` і `requireAdmin`.

## 11. Що можна зламати, тож будь обережним

- **`.env.local`**: не додавай у git, не показуй і не надсилай нікому. Якщо ключ потрапив на очі, створи новий.
- **Файли міграцій, що вже застосовані**: не редагуй. Нова зміна це новий файл.
- **`public/sw.js`**: після зміни іконок чи самого файлу збільш число `VERSION` у ньому, інакше телефони тримають старий кеш.
- **`public/.well-known/assetlinks.json` і ключ підпису Android**: без правильного відбитка застосунок покаже адресний рядок. Файли `signing.keystore` і `signing-key-info.txt` зберігай окремо й ніколи не клади в git.
- **Перевірка прав на сервері**: коли додаєш нову дію (`actions.ts`), починай її з `requireApproved` чи `requireAdmin`, а в SQL додавай умову власника `owner_id`. Приховати кнопку в інтерфейсі недостатньо.
- **Нові тексти**: додавай у всі чотири словники.

## 12. Перевірка після змін

З кореня проєкту:

    npx tsc --noEmit     # перевірка типів: шукає помилки до запуску
    npm run lint         # перевірка стилю коду
    npm run build        # повна збірка, як на Vercel

Якщо `tsc` скаржиться на «PageProps» або маршрут, що не існує, виконай `npx next typegen`.
Збірка на Vercel запускається сама після `git push`. Якщо змінювалась база, спершу виконай `npm run db:migrate`.

## 13. Де які технології

| Що | Чим |
|---|---|
| Фреймворк | Next.js 16 (App Router) |
| Мова | TypeScript, React 19 |
| Стилі | Tailwind CSS 4 |
| База даних | Neon Postgres (`@neondatabase/serverless`) |
| Вхід і реєстрація | Neon Auth (`@neondatabase/auth`) |
| Хостинг | Vercel |

**Серверні й браузерні файли.** Файл, що починається з `"use client"`, працює в браузері
(там кліки, поля, меню). Файл з `"use server"` це дії, які виконуються на сервері.
Усе інше (сторінки без цих позначок) малюється на сервері, і саме там безпечно читати базу.
